# 0-CODE

**الإصدار:** v2.1.1

دورة تطوير ذاتية لـ **Claude Code وCodex وOpenCode** تُدمج في مشروع قائم. يمكن لتوجيه دورة واحد أن يجمع البحث والتنفيذ والإصلاحات والتدقيق وإصدار النسخ.

## الدمج بواسطة وكيلك

اطلب في جلسة وكيل المشروع: **«ادمج 0-CODE من https://github.com/0-SOFT/0-CODE واتبع ملف `INTEGRATE.md` فيه».** استخدم نسخة من المصدر العام خارج المشروع المستهدف، ويمكن اختيار وسم إصدار محدد. يخدم [القالب القصير نفسه](INTEGRATE.md) التحديث والإزالة في المحركات الثلاثة.

يجرد الوكيل الوثائق والأدوات وMCP وأوامر الفحص، ويحل الخيارات الملتبسة فعلًا، ويعرض الخطة ثم يثبت ويشغل doctor ويلتزم بالتغييرات في فرع منفصل. أدوات المشروع لها الأولوية. [البدء اليدوي](QUICKSTART.md).

## ما الذي يُثبَّت

توجد شيفرة الإطار والإعدادات والمخططات والوحدات والقوالب المدمجة في **`.0-code/`**. وثائق الدورة ملك للمشروع وتوجد في **`.0-code/docs/`**؛ وملفات التشغيل والنسخ الاحتياطية في **`.0-code/run/`** المستثنى من Git. يضيف الدمج العادي الخطافات والتعليمات والأدوات المتوافقة وإضافة حماية OpenCode اللازمة للمحركات المختارة؛ أما جلسة Claude المعزولة الموضحة أدناه فتبقي دمجها داخل `.0-code/`. تُحفظ الشيفرة والوثائق القائمة وتُبلغ التعارضات والملفات المملوكة المعدلة قبل الكتابة.

[PROJECT_SETTINGS](docs/PROJECT_SETTINGS.md) هو مرجع الإعدادات الوحيد. يمكنك قبول الوثائق الافتراضية أو تغيير أدوار معينة أو ربط جميع الأدوار بتقاليد المشروع القائمة. تظل الحالة وثيقة قابلة للقراءة آليًا. تستخدم الوثائق البشرية اللغة المحددة، وتبقى تعليمات الوكيل بالإنجليزية.

النموذج وجهد الاستدلال وتسجيل الدخول تحت سيطرة المالك. أولوية الإعدادات هي **الخيارات الصريحة > البيئة > إعدادات المشروع > تفضيلات المحرك الأصلية**. يرث النموذج والجهد غير المحددين الإعدادات القائمة؛ لا تُنسخ بيانات المصادقة أبدًا. انظر [إعدادات المحركات](docs/ENGINE_SETTINGS.md).

يحتوي [الفهرس العام](toolset/CATALOG.md) على **خمسة خوادم MCP افتراضية: context7 وplaywright وchrome-devtools وsequential-thinking وmemory**. تحتاج حزم npm بإصدار يساوي الحد الأدنى المختبر وفق SemVer أو يزيد عليه، مع اسم الحزمة ونقطة الدخول الصحيحين؛ احتفظ بالإصدارات الأحدث الصالحة. لا تحتاج مفتاح API خارجيًا؛ وتحتاج أدوات المتصفح أيضًا متصفحًا متاحًا. التسجيل ونجاح doctor لا يثبتان اتصالًا فعليًا. تُستثنى ملفات التنفيذ الخاصة للمهارات والوكلاء والأوامر والقواعد. تبقى أمثلة خدمات الحسابات الاختيارية في بيان MCP معطلة حتى إعدادها والتصريح لها صراحة.

الافتراضي هو **تثبيت أدوات مستقل واحد لكل مستخدم** تشترك فيه مشاريعه. لا يغير تكرار الاختيار نفسه شيئًا. يثبت نطاق project اختيارًا مختلفًا لمشروع معين. لا تثبت إجراءات install/upgrade/migrate لجلسة Claude المعزولة أدوات المستخدم تلقائيًا؛ بل يلزم طلب `install-tools` صراحة وبشكل منفصل. إزالة المشروع تبقي أدوات الجهاز؛ يزيلها `uninstall-tools` منفصلًا ويعيد إعداداتها الأصلية. لا تُنسخ بيانات المصادقة أبدًا. [الإعدادات والمتطلبات](docs/PROJECT_SETTINGS.md).

## الوثائق والترحيل وعزل الجلسة في 2.1.1

تضع التثبيتات الجديدة الأدوار التسعة تحت `.0-code/docs/`: `STATE.md` و`ROADMAP.md` و`reports/` و`decisions/` و`todo/` و`logs/` و`prompts/` و`prompts/templates/` و`userdocs/`. احفظ الوثائق الدائمة في Git؛ تُستثنى سجلات الجلسات. يمكن وضع السجلات أيضًا في `.0-code/run/logs/`، ولا يجوز وضع الأدوار الدائمة في runtime. تظل الأدوار الخارجية الصريحة مدعومة ويحافظ upgrade العادي على المسارات. الوثائق خارج إيصال الملكية: يقبلها doctor ويحفظها upgrade ويُبقيها uninstall مع مجلداتها مع حذف بيانات التشغيل والنسخ الاحتياطية.

انقل أدوار 2.0.x القياسية من `docs/*` صراحة عبر `upgrade --relocate-documents <files.json>` أو `migrate --relocate-documents <files.json>` مع `--dry-run` أولًا. راجع قائمة الملفات الدقيقة؛ تبقى وثائق المنتج غير المدرجة. تُحدّث الإعدادات ومؤشرات STATE والقوالب المختارة مع أرشفة البايتات الأصلية المعدلة. تبقى المسارات الخارجية المخصصة كما هي. قبل النقل أو تبني التثبيت، أنهِ الدورة واجمع نتائج الأعمال الخلفية وأوقف المشغل؛ يؤدي قفل نشط أو مدخلات متغيرة إلى الرفض. جهز حركات الملفات معًا في Git للتعرف على إعادة التسمية.

يستخدم تثبيت `.0-code/` المعدل بلا إيصال `migrate --adopt-manifest <manifest.json>` مع قيم SHA-256 مراجعة وإجراءات `replace`/`preserve`. لا تُحفظ إلا امتدادات المشروع المدرجة بدقة في `bin/` و`claude/` و`.0-code/README.md`؛ تُستبدل الشيفرة وتُؤرشف. تظل الامتدادات قابلة للتعديل وتبقى بعد upgrade/uninstall. تؤدي الملفات المجهولة أو اختلاف البصمات إلى الرفض؛ التبني ونقل الوثائق عمليتان منفصلتان. احفظ قواعد AGENT الخاصة كوثيقة واربطها عبر `instructions.project_rules` قبل استبدال الدليل المولد.

تتطلب جلسة Claude المعزولة معًا `instructions.claude: session-hook` و`instructions.claude_settings: .0-code/claude/settings.json`. عند اختيار Claude وحده وأدوار وثائق داخلية، لا تنفذ install وupgrade وmigrate وتبنّي التثبيت أي كتابة أو حذف أو تعديل استرداد خارجي لم يُختر، بما في ذلك `.claude/` و`.mcp.json` و`CLAUDE.md`. أدوار الوثائق الخارجية الصريحة والمحركات الأخرى المختارة وطلب `install-tools` المنفصل استثناءات محدودة بنطاقها. إيصالات الملكية وسجلات المعاملات القديمة لا تسمح بتنظيف خارجي؛ ويُرفض الانتقال الذي يتطلبه قبل الكتابة ويلزم تنظيف مراجع في الوضع السابق. يحتفظ الدمج العادي `project-file` و`session-hook` مع `.claude/settings.json` بالتوصيل الأصلي.

شغّل `claude --settings .0-code/claude/settings.json` أو مشغلًا مراجعًا يمرر هذا الملف. يعرض SessionStart وSubagentStart عبر `.0-code/AGENT.md` مصادر المنسق الداخلي وإجراءات التدقيق المفعلة؛ ولا تُسجَّل أوامر slash أصلية. عند `modules.audits: false` تغيب مصادر التدقيق ومراجعها. يمكن إتاحة أدوات النص الآمنة بالمراجع؛ أما ضوابط التنفيذ الأصلية وتسجيلات MCP الجديدة التي لا يمكن توصيلها بهذه الطريقة فتُبلغ بحالة `unsupported`. تبقى ملفات المشغل وMCP وsystem-prompt وسياسات الإعدادات المحفوظة؛ تُضاف إدخالات الإطار إلى الإعدادات المتوافقة ويعيد uninstall قيمها الأصلية. الجلسات العادية لا تحمل الملف تلقائيًا. يفحص doctor الخطافات المحلية، لا تجاوزات المستخدم أو الإعدادات المدارة أو CLI. [الصيغ والأوامر والحدود](docs/PROJECT_SETTINGS.md).

تُسجَّل المنصات وإصدارات Node المختبرة وحدود نظام الملفات ومعايير التغطية في [نطاق التحقق](docs/PROJECT_SETTINGS.md#validation-scope). إعداد مصفوفة CI لا يثبت تنفيذها.

## العمل والصيانة

من المشروع المثبت:

```bash
node .0-code/tools/0code.mjs doctor --json
node .0-code/tools/0code.mjs start <cycle-prompt> --max 60
node /path/to/new-source/tools/0code.mjs upgrade --project . --dry-run
node .0-code/tools/0code.mjs uninstall --dry-run
```

املأ القالب الوحيد `.0-code/templates/cycle.md`. يكتب `start` الحالة ذريًا ويعرض أمر المشغل. أعد تشغيل Claude لتحميل الخطافات؛ يستخدم Codex وOpenCode المشرف الخارجي. لكل مجلد دورة نشطة واحدة. حدود التكرار والإنفاق اختيارية؛ حد المال يحتاج بيانات تكلفة المشرف. سجل الأعمال الطويلة في الحالة بدل الانتظار في حلقات sleep.

يدعم المصدر العام التثبيت الجديد وتحديث بنية `.0-code/`. **لا يتوفر الترحيل التلقائي لتثبيتات 1.x القديمة في جذر المشروع دون `config/legacy-installations.json`، وهو مستثنى من الشجرة العامة.** استخدم `migrate --dry-run` ثم `migrate` فقط مع مصدر يحتوي أدلة الملكية من الإصدارات المنشورة. لا تُزال إلا الملفات المثبت انتماؤها للإطار بايتًا ببايت والكتل المملوكة المطابقة تمامًا؛ تبقى الوثائق وتُنقل بيانات التشغيل أو تُؤرشف مع نسخ احتياطية. أنهِ أي دورة قديمة نشطة أولًا؛ وعند غياب الأدلة احتفظ بالملفات القديمة وراجع ملكيتها قبل تعديلها.

تشرح [إعدادات المحركات](docs/ENGINE_SETTINGS.md) و[Claude](CLAUDE_CODE_SETUP.md) و[دليل التطوير](GUIDELINE.md) و[الأمان](SECURITY.md) التشغيل والتحقق. في المصدر شغل `node tests/run.mjs --coverage-min=80` و`bash tests/smoke.sh`؛ النتائج المحلية دليل، وتوافر CI مسألة منفصلة.
