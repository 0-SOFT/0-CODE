# 0-CODE

**Версия:** v2.1.1

Автономный цикл разработки для **Claude Code, Codex и OpenCode**, который встраивается в существующий проект. Один промпт цикла может объединять исследование, реализацию, исправления, аудиты и выпуск.

## Интеграция через агента

В сессии агента своего проекта напишите: **«Интегрируй 0-CODE из https://github.com/0-SOFT/0-CODE; следуй его `INTEGRATE.md`».** Используйте публичную копию исходников вне целевого проекта, при необходимости на выбранном теге выпуска. Один [короткий шаблон](INTEGRATE.md) также ведёт обновление и удаление во всех трёх движках.

Агент собирает опись документов, инструментов, MCP и команд проверок, разрешает только реальные неоднозначности, показывает план, устанавливает, запускает doctor и коммитит в отдельной ветке. Инструменты проекта имеют приоритет. [Ручной запуск](QUICKSTART.md).

## Что устанавливается

Код фреймворка, конфигурация, схемы, модули и встроенные шаблоны находятся в **`.0-code/`**. Документы цикла принадлежат проекту и хранятся в **`.0-code/docs/`**, служебные файлы и архивы — в исключенном из Git **`.0-code/run/`**. Обычная интеграция добавляет выбранным движкам необходимые родные хуки, инструкции, совместимые инструменты и плагин стража OpenCode; описанная ниже изолированная сессия Claude хранит свою интеграцию внутри `.0-code/`. Код и документы владельца сохраняются; конфликты и измененные собственные файлы обнаруживаются до записи.

Единственный справочник настройки — [PROJECT_SETTINGS](docs/PROJECT_SETTINGS.md). Можно принять документы по умолчанию, переопределить отдельные роли или связать все роли с принятой схемой проекта. STATE остаётся машинным документом. Человеческие документы пишутся на выбранном языке, инструкции агента — по-английски.

Модель, усилие рассуждения и вход принадлежат владельцу. Приоритет настроек: **явные флаги > окружение > конфигурация проекта > родные предпочтения движка**. Неуказанные модель и усилие наследуются; авторизация никогда не копируется. См. [настройки движков](docs/ENGINE_SETTINGS.md).

[Публичный каталог](toolset/CATALOG.md) содержит **пять штатных MCP: context7, playwright, chrome-devtools, sequential-thinking и memory**. Нужны npm-пакеты не ниже проверенной границы SemVer, с правильным именем и точкой входа; подходящие новые версии сохраняются. Внешний API-ключ не нужен; браузерным инструментам также нужен доступный браузер. Регистрация и успешный doctor не доказывают живое соединение. Приватные тела навыков, агентов, команд и правил исключены. Необязательные примеры учётных сервисов в манифесте MCP остаются выключенными до явной настройки и авторизации.

Умолчание — **одна независимая установка инструментов на пользователя**, общая для его проектов. Повтор того же выбора ничего не меняет. Область project закрепляет другой набор в проекте. Изолированные install/upgrade/migrate Claude не устанавливают пользовательские инструменты автоматически: нужна отдельная явно запрошенная команда `install-tools`. Удаление проекта оставляет машинные инструменты; `uninstall-tools` снимает их отдельно и восстанавливает прежние настройки. Авторизация не копируется. [Настройка и зависимости](docs/PROJECT_SETTINGS.md).

## Документы, перенос и изоляция сессии в 2.1.1

Новые установки размещают девять ролей в `.0-code/docs/`: `STATE.md`, `ROADMAP.md`, `reports/`, `decisions/`, `todo/`, `logs/`, `prompts/`, `prompts/templates/` и `userdocs/`. Постоянные документы следует хранить в Git; журналы исключены. Для журналов допустим также `.0-code/run/logs/`, для постоянных ролей runtime запрещен. Явные внешние роли поддерживаются, обычный upgrade сохраняет пути. Документы не входят в квитанцию владения: doctor их принимает, upgrade сохраняет, uninstall оставляет вместе с каталогами, удаляя runtime и архивы.

Перенос стандартных ролей 2.0.x из `docs/*` выполняется явно: `upgrade --relocate-documents <files.json>` или `migrate --relocate-documents <files.json>`, сначала с `--dry-run`. Проверьте точный список файлов: документация продукта вне списка остается на месте. Обновляются config, указатели STATE и выбранные шаблоны; исходные измененные байты архивируются. Нестандартные внешние пути сохраняются. Перед переносом или принятием установки завершите цикл, соберите фоновые работы и остановите драйвер; живой lock или изменение входов вызывает отказ. Добавляйте перемещения в Git вместе для распознавания переименований.

Доработанная установка `.0-code/` без квитанции принимается через `migrate --adopt-manifest <manifest.json>`: проверенные SHA-256 и действия `replace`/`preserve`. Сохранить можно только точно перечисленные проектные расширения в `bin/`, `claude/` и `.0-code/README.md`; код заменяется с архивированием. Расширения доступны для правок и сохраняются при upgrade/uninstall. Неизвестные файлы или несовпадение хешей вызывают отказ; принятие и перенос выполняются отдельно. Свои правила AGENT сохраните документом и подключите через `instructions.project_rules` до замены генерируемой инструкции.

Для изолированной сессии Claude нужны одновременно `instructions.claude: session-hook` и `instructions.claude_settings: .0-code/claude/settings.json`. Если выбран только Claude, а роли документов внутренние, install, upgrade, migrate и принятие установки не выполняют невыбранных внешних записей, удалений и изменений при восстановлении, включая `.claude/`, `.mcp.json` и `CLAUDE.md`. Явные внешние роли документов, другие выбранные движки и отдельная запрошенная команда `install-tools` дают только соответствующие исключения. Старые квитанции владения и журналы транзакций не разрешают внешнюю очистку: требующий ее переход отказывает до записи и требует проверенной очистки в прежнем режиме. Обычные `project-file` и `session-hook` с `.claude/settings.json` сохраняют родную доставку.

Запускайте `claude --settings .0-code/claude/settings.json` или проверенный лаунчер, передающий этот файл. SessionStart и SubagentStart через `.0-code/AGENT.md` дают ссылки на внутренние исходники оркестратора и включенных процедур аудита; родные slash-команды не регистрируются. При `modules.audits: false` исходников и ссылок аудита нет. Безопасные текстовые инструменты доступны по ссылке; несовместимые с этим способом средства управления выполнением и новые регистрации MCP получают `unsupported`. Сохраненные лаунчер, MCP, system-prompt и политики настроек остаются; совместимые настройки получают записи фреймворка, uninstall восстанавливает исходные значения. Обычные сессии не загружают этот файл автоматически. Doctor проверяет местные хуки, но не пользовательские, управляемые администратором или CLI-переопределения. [Форматы, команды и ограничения](docs/PROJECT_SETTINGS.md).

Проверенные платформы, версии Node, ограничения файловой системы и пороги покрытия приведены в [области проверки](docs/PROJECT_SETTINGS.md#validation-scope). Настроенная матрица CI не доказывает выполнение проверок.

## Работа и обслуживание

Из установленного проекта:

```bash
node .0-code/tools/0code.mjs doctor --json
node .0-code/tools/0code.mjs start <cycle-prompt> --max 60
node /path/to/new-source/tools/0code.mjs upgrade --project . --dry-run
node .0-code/tools/0code.mjs uninstall --dry-run
```

Заполните единственный `.0-code/templates/cycle.md`. `start` атомарно задаёт состояние и выводит команду водителя. Claude нужно перезапустить для загрузки хуков; Codex и OpenCode используют надзиратель. В одной папке один цикл. Пределы итераций и расходов добровольны; денежный предел требует данных стоимости от надзирателя. Долгую работу регистрируйте в STATE вместо опроса со сном.

Публичная копия поддерживает новую установку и обновление структуры `.0-code/`. **Автоматическая миграция старой 1.x с файлами в корне недоступна без `config/legacy-installations.json`, который исключён из публичного дерева.** Запускайте `migrate --dry-run`, затем `migrate` только из исходников с доказательствами владения из опубликованных выпусков. Снимаются только побайтно доказанные файлы и точные собственные блоки; документы остаются, служебные данные переносятся или архивируются с копиями. Сначала завершите живой старый цикл; без доказательств сохраняйте старые файлы и проверяйте владение до изменений.

[Настройки движков](docs/ENGINE_SETTINGS.md), [установка Claude](CLAUDE_CODE_SETUP.md), [руководство разработки](GUIDELINE.md) и [безопасность](SECURITY.md) описывают работу и проверку. В исходниках: `node tests/run.mjs --coverage-min=80` и `bash tests/smoke.sh`. Локальный результат — доказательство; доступность CI проверяется отдельно.
