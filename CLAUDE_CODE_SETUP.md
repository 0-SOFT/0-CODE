# Claude Code setup

Use the public source at `https://github.com/0-SOFT/0-CODE`. Follow [INTEGRATE](INTEGRATE.md) for the agent workflow or [QUICKSTART](QUICKSTART.md) for manual installation. Select `claude`; Codex and OpenCode use the same lifecycle CLI with their own adapters. All project options are defined once in [PROJECT_SETTINGS](docs/PROJECT_SETTINGS.md).

The installer merges required hooks into `.claude/settings.json` and a short owned reference into `CLAUDE.md` and `AGENTS.md`. Commands point into `.0-code/`; existing owner settings and instructions are preserved. Foreign Stop and PreToolUse control hooks are explicit collisions. There is no Claude plugin installation mode.

Restart the Claude session after installation or hook changes: settings load at session startup. Run `node .0-code/tools/0code.mjs doctor --json`, fill `.0-code/templates/cycle.md`, then use `start`. In the project session, follow the active state task. The Stop hook continues turns and checks genuine blockers, release completion and enabled limits. An external supervisor is an alternative driver; never start both for one folder.

Native login and personal MCP stay with Claude. Unspecified model and effort inherit owner preferences; precedence is explicit flags, environment, project configuration, then native settings. Authentication is never copied. The public catalog includes only five default MCP: context7, playwright, chrome-devtools, sequential-thinking and memory. Private tool bodies are excluded. Valid newer npm prerequisites are preserved; these five need no external API key, while browser tools need a browser. Default user tools use native user locations; choose the scope explicitly before installation. Stock tools do not add global cycle hooks or permissions. Use project scope for a project-specific selection. [ENGINE_SETTINGS](docs/ENGINE_SETTINGS.md) documents environment overrides, guard modes, headless permissions and native `ask` rules.

Session logs and usage status line are optional modules. Claude hooks capture native transcripts and summaries; the supervisor records attempt journals for all three engines under the configured logs role when `session_logs` is enabled, including failures and retries. Journals do not duplicate usage accounting. An existing status line is chained rather than replaced. Bot notifications require explicit Telegram credentials; without them notifications do not occur. Logs can contain owner data and belong in the ignored logs role.

Upgrade an existing `.0-code/` installation through the lifecycle CLI. The public source excludes `config/legacy-installations.json`; automatic migration of a root-based 1.x installation requires a separate source with published ownership evidence. Stop the old cycle, preview the migration and retain backups; without evidence, preserve old files and review their ownership.
